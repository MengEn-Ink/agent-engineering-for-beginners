# 会聊天，不等于会做事

你让 AI “帮我订一张明早去上海的票”，它礼貌地回复：“当然可以！以下是订票建议。”然后列出高铁、飞机和大巴的优缺点——唯独没有票。

它没有偷懒。它只是完成了一个**回答任务**，而你期待的是一个**交付任务**。两者之间隔着工具、状态、权限、控制流、验证和失败恢复。Agent 工程研究的，就是怎样把这段距离修成一条能走、能检查、走错还能回来的路。

<SystemStack />

## 这本书适合谁

- 你是产品、运营或设计，想知道工程师为什么总问“失败以后怎么办”；
- 你会调用模型 API，却发现 Demo 很聪明，上线后像刚入职又不看群消息的实习生；
- 你负责技术方案，需要判断该用固定 Workflow、单 Agent，还是多 Agent；
- 你不准备研究模型训练，但想看懂一个 AI 系统怎样可靠地工作。

这不是框架说明书。书里不会用几十页教你背某个 SDK 的函数名，因为函数会变，工程问题不会：目标是否清楚？工具是否可控？状态是否可恢复？结果是否有证据？边界是否守得住？

## 我们怎样保证内容可信

本书把资料分为三档：协议、官方文档和官方仓库属于 A 级；署名明确的工程复盘与正式书籍属于 B 级；社区教程和排行榜属于 C 级。关键事实至少需要一条 A 级来源，或两条相互独立的 B 级来源。C 级资料只负责提供线索，不能单独给结论盖章。

所有案例都经过重新叙述。公众号文章用于选题，不搬运原图和大段原文；本地工程项目只抽取通用模式，不公开内部地址、账号、标识、日志、源码或尚未发布的能力。

## 读完以后，你应该会问什么

看到一个“AI 员工”方案时，先别问模型多大，先问七件事：

1. 它最终要交付什么？
2. 它能看见哪些上下文？
3. 它能调用哪些工具？
4. 任务状态存在哪里？
5. 下一步由规则还是模型决定？
6. 我们怎样证明结果正确？
7. 失败、越权或不确定时，谁来接管？

如果这七个问题都有朴素、具体、可检查的答案，你已经站在 Agent 工程的门里了。

> 这本书的目标不是让你“相信 Agent”，而是让你知道什么时候可以信、信到哪一步，以及不该信时系统怎样刹车。

# 《别只会和 AI 聊天》完整手册与阅读主题改版设计

日期：2026-09-25  
状态：用户已批准方案 B，待书面复核

## 1. 改版目标

把当前“10 篇精炼导读”升级为一本可持续阅读、可直接用于方案评审的 Agent 工程入门手册，同时把阅读页从高视觉刺激的展示风格调整为低干扰、长时间阅读优先的编辑风格。

首版基线：

- 10 个主章节，每章约 1,859–2,239 个中文字符；
- 章节总量约 20,900 个中文字符；
- 全站使用固定网格背景，荧光绿、珊瑚橙、深墨蓝承担大面积视觉元素；
- 章节具备故事、概念、踩坑与小测，但缺少足够的设计步骤、连续案例、模板和应用方向。

新版验收目标：

- 14 个主章节，正文总量 65,000–82,000 个中文字符；
- 原 10 章扩展到每章 4,700–6,000 个中文字符；
- 新增 4 章应用篇，每章 4,500–5,500 个中文字符；
- 阅读页采用安静纯色背景、稳定字号和行宽；
- 首页保留品牌辨识，强配色只用于首页、图解和语义提示；
- 所有扩写内容继续满足来源分级、公开边界和可访问性门禁。

## 2. 读者体验原则

### 2.1 阅读页优先于展示页

首页负责建立品牌和阅读入口，允许更强的构图与色彩。章节页负责连续阅读，默认不显示网格纹理、固定背景、重阴影或大面积高饱和色。

### 2.2 每章既能顺读，也能拿来工作

章节不仅解释概念，还提供判断方法、工程步骤、案例、模板和练习。读者读完后应能拿着本章检查自己的方案，而不是只记住一个比喻。

### 2.3 复杂概念先给地图，再给细节

每章开头给出本章问题、学习结果和一张概念图；正文按“为什么 → 系统怎么工作 → 怎样设计 → 哪里会失败 → 怎样检查”推进。

## 3. 内容架构

全书改为四篇、14 章。

### 第一篇：认识 Agent

1. AI Native 到底 Native 在哪
2. Prompt、Workflow、Agent 的选择梯
3. ReAct：观察、行动、验证与停止

### 第二篇：组装 Agent

4. 工具与 MCP：能力、契约与权限
5. 状态与记忆：上下文、任务、知识和审计
6. Loop 到 Graph：分支、并行、等待与恢复
7. 多 Agent：专业化、交接和协调成本

### 第三篇：让 Agent 敢上线

8. 评测与可观测性：从一次答对到持续证据
9. 失败与恢复：超时、幂等、补偿和人工接管
10. 从 Demo 到生产：发布、灰度、运营与复盘

### 第四篇：应用方向

11. 研究型 Agent：问题拆解、搜索、来源与事实核验
12. 客服与运营 Agent：知识、流程、情绪与升级人工
13. Coding Agent：仓库理解、计划、执行、测试与代码审查
14. Computer Use / 浏览器 Agent：视觉状态、操作证据与高风险边界

附录继续保留术语表、评审清单和延伸阅读，并新增“章节模板下载”和“应用选型矩阵”。

## 4. 每章内容结构

每章包含 7 个必备模块，保证完整但不机械复制版式：

1. **本章先回答什么**：3 个问题、学习结果与预计阅读时间；
2. **概念地图**：一张核心原创图解释组件及关系；
3. **工程拆解**：解释状态、接口、控制流与不变量；
4. **设计步骤**：4–7 个可执行步骤；
5. **案例与失败边界**：展示正确路径和至少一个关键失败；
6. **可复制资产**：模板、决策表或检查清单；
7. **练习、参考答案与来源**：帮助读者落地并追溯事实。

每章再从以下模块中选择至少 2 个，按主题需要组合：

- 生活化开场；
- 交付型 Agent 连续案例；
- 研究、客服、Coding 或 Computer Use 应用切片；
- 失败实验或事故复盘；
- 方案对比；
- 成本与性能讨论；
- 实施清单；
- 扩展阅读。

每章至少 1 张核心概念图。第二个视觉表达按需要选择流程图、决策表、对比图或状态时间线，不为满足数量强行绘图。装饰性图片不计入解释性视觉。

## 5. 连续案例设计

“交付型 Agent”不再只出现在独立案例页，而是贯穿 10 个基础章节：

| 章节 | 连续案例问题 |
| --- | --- |
| AI Native | 从聊天入口改成可交付流程 |
| Workflow / Agent | 哪些节点固定，哪些允许动态判断 |
| ReAct | 如何读取环境反馈并停止 |
| 工具与 MCP | 工具契约、权限和回执 |
| 状态与记忆 | Run ID、任务状态和审计记录 |
| Graph | 分支、等待批准和恢复 |
| 多 Agent | 执行者与审判者如何交接 |
| 评测 | 结果、轨迹、证据和失败分类 |
| 安全恢复 | 幂等、补偿、沙箱和人工接管 |
| 生产化 | 影子、告警、阻断和持续运营 |

案例必须保持泛化，不出现内部地址、账号、产品标识、凭证、日志、报告、私有路径、源码片段或未公开能力。

## 6. 阅读主题设计

### 6.1 页面分区

- **首页**：保留“工程手册 + 编辑海报”风格；网格只出现在首屏局部，且对比度极低；
- **章节页**：纯色阅读背景，不显示全局网格；
- **图解**：独立容器内使用深墨蓝、低饱和青绿和低饱和陶土色；
- **提示**：风险、结论、练习用轻量左边线或浅色底，不使用重阴影卡片。

### 6.2 颜色

亮色阅读主题：

- 页面背景：`#FCFCFA`
- 次级背景：`#F4F3EE`
- 正文：`#202632`
- 次级文字：`#596170`
- 链接与焦点：`#175CD3`
- 成功/行动：`#287A53`
- 风险：`#B54732`
- 分隔线：`#D9DCE2`

深色阅读主题：

- 页面背景：`#17191D`
- 次级背景：`#20232A`
- 正文：`#ECEEF2`
- 次级文字：`#B6BCC8`
- 链接与焦点：`#8AB4FF`
- 成功/行动：`#7DD3A7`
- 风险：`#F2A38F`
- 分隔线：`#343944`

原荧光绿和珊瑚橙只保留为首页品牌装饰或小面积图解编码，不承担长段文字背景。首页首屏高饱和色面积不得超过约 10%，正文页完全禁用高饱和大色块。

### 6.3 排版

- 正文桌面字号：17–18px；移动端：16.5–17px；
- 正文行高：1.85–1.95；
- 正文可读行宽：680–740px，约 38–42 个汉字；
- 段间距：1.1–1.35em；
- 章节 H1：桌面不超过 48px，移动端不超过 36px；
- H2 以留白与细分隔线建立层级，不使用 2px 深色硬线；
- 标题启用 `text-wrap: balance`，正文启用 `text-wrap: pretty`；
- 标题锚点设置 `scroll-margin-top`，避免被固定导航遮挡。

### 6.4 动效与交互

- 取消所有正文子元素逐个入场动画；
- 首页只保留一次轻量首屏进入；
- 图解仅在 hover / focus 时强化当前节点，不移动正文布局；
- 完整支持 `prefers-reduced-motion`；
- 所有自定义链接和按钮有清晰 `:focus-visible`；
- 深色主题在根元素设置 `color-scheme: dark`。

## 8. 内容生产与核验流程

1. 每章先定义学习结果和新增内容清单；
2. 从 A/B 级来源提取可验证事实，版本相关能力标访问日期；
3. 写工程解释、案例和模板，不复制外部文章结构与措辞；
4. 更新 `sources/source-index.yml` 和章节来源引用；
5. 自动检查篇幅、固定结构、组件数量、来源 ID 和公开边界；
6. 审判者按“事实—采纳—风险—结论”复核；
7. 通过桌面、390px、深浅色、搜索、键盘、对比度和 Pages 回归后发布。

### 8.1 应用篇的一手来源与失败边界

应用篇不能只引用框架宣传页。每章至少包含 2 条 A 级一手来源，其中至少一条来自规范、官方安全文档、正式论文或官方工程复盘，并明确不适用范围：

| 应用章 | 一手来源方向 | 必须覆盖的失败边界 |
| --- | --- | --- |
| 研究型 Agent | 搜索/引用规范、官方评测资料、可验证研究型 Agent 论文或官方实现 | 引用不存在、来源循环引用、过期事实、只搜到支持原假设的证据 |
| 客服与运营 Agent | 官方工具调用、guardrail、企业 Agent 工程案例 | 错误承诺、越权退款、知识过期、情绪升级失败、人工接管丢上下文 |
| Coding Agent | 官方 Coding Agent 文档、仓库级工程实践、软件测试与安全资料 | 改错仓库、隐藏测试未过、依赖/凭证泄露、只修表象、未验证即提交 |
| Computer Use / 浏览器 Agent | 官方 Computer Use/浏览器控制文档、安全与提示注入资料 | 看错页面状态、点击不可逆动作、跨域泄露、视觉误识别、操作后未取证 |

每个应用章必须明确：适合做什么、不适合做什么、最低权限、可接受损失、人工接管点和最终业务证据。

## 9. 验收标准

### 内容

- 14 个主章节全部完成；
- 总正文 65,000–82,000 个中文字符；
- 原 10 章每章 4,700–6,000 个中文字符；
- 新 4 章每章 4,500–5,500 个中文字符；
- 每章 7 个必备模块完整，另有至少 2 个按主题选择的模块；
- 每章至少 1 张核心概念图，第二视觉表达按实际解释需要选择；
- 每章包含可复制模板或决策表、案例与失败边界、练习和答案；
- 关键事实满足 A 级单源或两条独立 B 级来源。

### 可读性

- 阅读页无全局网格、无固定背景纹理；
- 首页网格仅限首屏局部且为极低对比度，高饱和色面积不超过首屏约 10%；
- 亮色与深色正文对比度达到 WCAG AA；
- 390px 无横向溢出，表格可安全滚动；
- 正文行宽、字号、行高满足本设计参数；
- 自定义交互有 `focus-visible`，标题锚点不被导航遮挡；
- 减少动态偏好下无非必要动画。

### 工程与发布

- 自动测试覆盖章节数量、长度、结构、图解、来源与主题 token；
- `pnpm validate`、`pnpm build` 和 dist 泄露检查通过；
- 公开路由、搜索、主题、favicon 和 Pages 资源均正常；
- 过程文档继续排除在 VitePress 发布面；
- GitHub Actions 成功，线上地址返回 HTTP 200。

## 10. 非目标

本轮不做后端、登录、评论、阅读进度云同步、付费、多语言、在线 AI 问答或精排 PDF。目标是把当前公开网站升级为内容扎实、长时间可读的中文 Agent 工程入门手册。

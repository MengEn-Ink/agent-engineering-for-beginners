# 术语表：把黑话翻译成人话

同一个词在不同框架里可能有不同边界。本页给出的是便于工程协作的工作定义，不宣称它们是唯一标准。

## Agent

以模型为动态决策组件，结合上下文、工具、状态、控制流和验证，持续朝目标行动的系统。它不是“模型换个名字”，也不一定高度自治。

## Workflow

由代码或配置预先规定主要步骤和分支的流程。模型可以参与某些节点，但路径的控制权主要在系统设计者手中。固定任务优先考虑 Workflow，通常更便宜、更稳定。

## Tool

Agent 可调用的外部能力，例如搜索、读文件、查订单或创建草稿。一个好工具有明确输入、输出、副作用、权限和错误结构。

## MCP

Model Context Protocol，一种让 AI 应用与能力提供方标准化连接的协议。它定义 Host、Client、Server 以及 Tools、Resources、Prompts 等原语，但不自动解决业务授权和安全。

## RAG

Retrieval-Augmented Generation，检索增强生成。系统先从外部知识中取回相关材料，再让模型据此回答。检索结果仍需核对来源、版本和时效。

## Memory

系统跨步骤或跨会话保留的信息能力。工程上应区分会话上下文、任务状态、长期偏好、知识库和审计记录，而不是把所有历史塞进一个大字段。

## Graph

用节点和边表达控制流的方式。节点负责一个步骤，边表示转移条件。Graph 能让分支、并行、等待和恢复更显式，但不会自动让模型更聪明。

## Eval

Evaluation，评测。通过任务结果、工具轨迹、业务证据、人工判断、成本和延迟等指标，系统地判断 Agent 是否满足目标。一次演示成功不等于通过评测。

## ReAct

Reasoning + Acting 的 Agent 模式。工程上可理解为：维护可审计计划摘要，执行动作，观察环境结果，再决定下一步。应有停止条件，不公开模型私有思维链。

## Handoff

Agent、流程或人之间的任务交接。好的 handoff 包含目标、事实、已完成动作、证据、未决问题、期望输出和任务标识，而不是整段复制聊天记录。

## Guardrail

对输入、输出或工具调用进行检查和限制的机制。Guardrail 是纵深防御的一层，不能替代最小权限、沙箱、幂等和人工接管。

## Human-in-the-loop

人类在系统关键节点参与判断、批准或纠错的机制。完整设计需要规定触发条件、证据展示、可选动作、超时和拒绝后的恢复路径。

## Idempotency / 幂等

同一个操作被重复请求时，业务结果仍等价于只执行一次。付款、发消息、创建资源等写操作在自动重试前尤其需要幂等设计。

## Fail-closed / 失败关闭

当状态未知、证据不完整或检查失败时，系统默认不放行。它与“没看到错误就算成功”相反。

## Observability / 可观测性

通过任务标识、版本、状态、工具调用、证据、延迟、费用和失败分类理解系统实际发生了什么。它不等于“有很多日志”。

# Agent 应用选型矩阵

不要从框架出发找场景。先回答任务怎样变化、错误会造成什么、结果如何证明，再选择 Prompt、Workflow、Agent 或多 Agent。

| 场景 | 主要不确定性 | 推荐起点 | 最低权限 | 关键证据 |
| --- | --- | --- | --- | --- |
| 内容摘要 | 表达与压缩 | Prompt | 只读给定材料 | 覆盖要点、无新增事实 |
| 固定审批 | 规则与状态 | Workflow | 受限业务 API | 节点状态、审批记录 |
| 公开研究 | 搜索路径与证据冲突 | Agent + 证据 Workflow | 只读网络 | 主张—来源表 |
| 客服问答 | 意图与知识匹配 | 路由 Workflow | 只读用户范围 | 政策版本、回答摘要 |
| 退款处理 | 资格、金额与副作用 | Workflow + Agent 辅助 | 草稿起步 | 订单状态、批准、回执 |
| 代码修复 | 仓库探索与验证 | Coding Agent | 独立分支 / worktree | 红绿测试、diff、构建 |
| 浏览器表单 | 页面状态与定位 | Computer Use Agent | 单站点、草稿 | 动作前后状态、对象 ID |
| 跨域复杂研究 | 并行子问题 | 有限多 Agent | 分角色只读 | 独立来源、handoff、汇合 |

## 选择顺序

1. 结果能否用一次结构化生成完成？先用 Prompt。
2. 主要路径能否预先写出？先用 Workflow。
3. 是否必须根据环境反馈动态选择下一步？再用 Agent。
4. 是否存在真实的上下文、权限或并行边界？最后考虑多 Agent。

## 风险顺序

先只读，再草稿；先批准后执行，再考虑有限自动。门禁执法强度 `shadow → warn → block` 与 Agent 权限 `read-only → draft → approval-required → limited-auto` 是两条独立轴，不混成一条成熟度阶梯。

## 快速结论

最合适的架构不是最复杂的，而是用最低复杂度满足目标、证据和风险要求的那一个。选择后仍需用真实基线证明它比上一层更好。

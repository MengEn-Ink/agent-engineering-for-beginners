# Agent 方案评审清单

打印或复制这页，在方案评审时逐项回答。任何一项“说不清”都不是羞耻，而是下一步该做的工程工作。

## 适用性

- [ ] 最终交付物可被具体描述，而不是“提升体验”
- [ ] 已写出必须做到和绝不能做的结果
- [ ] 有一次 Prompt 或固定 Workflow 的基线数据
- [ ] 能说明为什么固定流程无法覆盖关键路径
- [ ] 动态决策带来的价值大于新增复杂度
- [ ] 已确定哪些决定必须由代码或人掌握

## 可靠性

- [ ] 每次运行有唯一任务标识
- [ ] 关键状态不只存在于聊天上下文
- [ ] 工具输入、输出和错误结构清楚
- [ ] 每个行动后都有业务级验证
- [ ] 有步数、时间、费用和重复动作限制
- [ ] 未执行、未知和缺证据不会被判为通过
- [ ] 历史故障已进入回归评测集

## 安全

- [ ] 工具遵循最小权限并限制目标范围
- [ ] 凭证不进入代码、Prompt、日志和报告
- [ ] 写操作区分可逆、高影响和不可逆风险
- [ ] 高风险操作有执行前批准
- [ ] 页面、文件、日志和工具结果按不可信数据处理
- [ ] 沙箱同时限制文件、进程、网络和资源
- [ ] 人工接管有证据、超时、拒绝和恢复路径

## 成本

- [ ] 记录每个成功任务的平均模型与工具成本
- [ ] 记录平均步骤数、重试数和上下文大小
- [ ] 监控 p50 与尾部延迟，而不只看平均值
- [ ] 多 Agent 的每个角色都证明了增量价值
- [ ] 可用更小模型或确定性逻辑处理简单节点
- [ ] 达到预算时能有尊严地停止并返回进度

## 运营

- [ ] 模型、Prompt、工具、图和数据版本可追踪
- [ ] 失败分类直接对应责任人和恢复动作
- [ ] 有影子运行、告警和阻断的升级路径
- [ ] 用户能知道系统在做什么、为什么暂停
- [ ] 长期记忆可查看、纠正、过期和删除
- [ ] 发布后持续抽样复核并更新评测集
- [ ] 事故复盘会修改门禁，而不只修改说明文档

## 一句话结论模板

> 这个任务适合使用 **Prompt / Workflow / Agent / 多 Agent**，因为主要不确定性是 ______；系统只允许它 ______，通过 ______ 证明完成，在 ______ 时暂停并交给 ______。

如果这句话填不完整，先不要讨论框架选型。

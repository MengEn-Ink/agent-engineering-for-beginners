# 前沿雷达：先观察，再写进教材

Agent 工程变化很快，但“每条新闻都改正文”会让一本书变成追热点的草稿箱。前沿雷达承担缓冲层：它记录真正可能改变工程实践的更新，说明证据和影响，却不自动把新名词升级成最佳实践。

## 三层知识，不混在一起

| 层级 | 放什么 | 更新方式 |
| --- | --- | --- |
| 常青正文 | 问题拆解、工具契约、状态、评测、权限、恢复等稳定方法 | 证据成熟、影响明确后人工修订 |
| 前沿专题 | 已经值得学习，但接口或共识仍可能变化的技术 | 标明版本、成熟度和复核日期 |
| 月度雷达 | 协议发布、标准倡议、风险研究和工程方法变化 | 每月精选 5–8 条，先记录再判断 |

## 每条更新必须回答什么

雷达条目必须写清日期、状态、成熟度、发生了什么、为什么重要、影响章节、当前决定和 A 级证据。`watch` 表示继续观察，`adopt` 表示先进入前沿专题，`revise` 表示已有正文需要人工修订。

自动巡检只负责发现链接失效、重定向、版本页变化和仓库归档。它可以创建待审 Issue，但不能自动读取外部网页后改写正文，更不能绕过人工复核直接发布结论。

## 怎样读雷达

如果你刚入门，先读正文，把雷达当“将来会遇到的变化”。如果你在设计生产系统，优先查看条目的影响章节和当前决定，再回到官方来源验证版本。任何带 `watch` 的内容都不应被写进长期兼容承诺。
